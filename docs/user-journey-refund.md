# 사용자 저니: 이월결손금 누락을 찾아 경정청구까지 (Phase 2 기록)

- 작성일: 2026-11-01
- 용도: 개발자(본인)가 실제로 겪은 **이월결손금 누락 발견 → 경정청구 → 사후 처리** 과정을 일반 사용자의 여정으로 바꿔 둔 기록이다. R1(환급 점검, [PRD-refund-check.md](PRD-refund-check.md))을 만든 근거이고, **Phase 2**에서 무엇을 더 만들지 정할 때 쓴다.
- 원본 경험의 세부(금액·연도별 값·신고 이력)는 개인 정보라서 **볼트의 `source-docs/`에만** 있다(`summary-2026-11-01.md`, `self-refund-claim-2025.md`, `loss-carryforward-analysis.md`, `hometax-claim-input-sheet-2025.md`, `hometax-filing-history.md`). 이 문서에는 금액을 쓰지 않는다.
- 법령·홈택스 화면은 직접 확인하지 못한 부분이 있다. `[확인 필요]`로 표시했다. 세무 상담이 아니다.

---

## 1. 누구의 여정인가

| 페르소나 | 상황 | 특징 |
|---|---|---|
| **A. 직접 신고하는 임대사업자** (주 대상, 본인 사례) | 근로소득이 있고 상가 임대 소득이 따로 있음. 간편장부로 신고하다 복식부기로 바꾸는 중. 과거에 결손이 난 해가 있음 | 세금 용어가 낯설고, 홈택스는 쓸 줄 알지만 "무엇을 확인해야 하는지"를 모름. 시간은 있으나 불안이 큼 |
| **B. 가족 신고를 도와주는 사람** | 부모님 임대 소득 신고서를 정리해 줌 | 서류가 여러 사람 것이라 섞이기 쉽고, 본인이 아니라 대리로 로그인할 수 없는 부분이 있음 `[확인 필요]` |
| **C. 세무사 없이 시작했다가 점검받고 싶은 사람** | 신고는 끝났는데 맞는지 확신이 없음 | 결과 점검만 원함. 청구까지 갈지는 결과에 따라 |

이 문서의 기준은 **A**이다. B·C는 차이가 나는 곳에만 표시한다.

## 2. 원본 경험의 흐름 (실제로 한 일)

번호는 아래 저니 단계와 같다.

1. 올해 신고서를 보다가 **이월결손금 공제가 0으로 되어 있음**을 알아챈다(명세서가 비어 있음).
2. 홈택스에서 **과거 신고 이력**(정기·수정·경정청구가 여러 건 섞여 있음)을 조회한다. 한 번에 최대 1년 단위로 나눠 조회.
3. 연도별 **신고서 PDF**를 받는다(최신본인지 구분해야 함).
4. 연도별 **소득·결손표**를 직접 만든다. 같은 해인데 신고서마다 숫자가 다른 곳을 발견한다.
5. 어느 숫자가 **확정**인지 정한다(예전에 낸 경정청구가 인정되었는지가 열쇠).
6. 발생 합계에서 이미 공제한 금액을 빼 **현재 잔액**을 재구성하고, 어느 해에 누락이 생겼는지 찾는다.
7. 청구 **요건**을 확인한다(승인 여부, 장부 보관, 기한).
8. 청구하면 **얼마가 돌아오는지** 계산한다(소득세, 지방소득세는 별도).
9. **범위를 정한다**: 이월결손금만 청구하고 다른 쟁점(간주임대료 등)은 따로 둔다. 같은 시기 **다른 납부 일정**(중간예납)을 먼저 처리한다.
10. 홈택스 **입력 순서 시트**를 만든다(화면 순서대로 값을 정리).
11. 홈택스에서 **경정청구**를 작성한다: 신고서 불러오기 → 이월결손금명세서 입력 → 세액 자동 계산 확인 → 청구 이유 선택 → 환급계좌.
12. **제출 오류**를 만나 고친다(청구 이유 분류 선택 등).
13. **부속·증빙서류**(발생 연도 신고서 PDF)를 제출한다.
14. 접수증을 저장하고, **지방소득세 환급 신청**(별도 사이트)과 결과 확인(약 2개월 `[확인 필요]`)을 할 일로 남긴다.
15. 다음 해 신고를 위해 **이월 잔액**을 기록한다.

## 3. 일반 사용자 저니

저니는 8개 단계다. 각 단계에 사용자가 하는 일, 생각·감정, 막히는 곳, 필요한 도움을 적었다. "R1" 열은 지금 만든 환급 점검이 어디까지 돕는지다.

### 단계 1. 의심이 생긴다 (인지)

| 항목 | 내용 |
|---|---|
| 계기 | 신고서에서 이월결손금 칸이 비어 있음을 우연히 봄 / 블로그·지인에게서 "결손금이 이월된다"는 이야기를 들음 / 환급 사례 글을 읽음 |
| 하는 일 | "나도 해당되나?"를 검색한다. 과거에 결손이 난 해가 있었는지 떠올린다 |
| 생각·감정 | 막연한 불안, "내가 놓쳤나?" / 세금 용어가 무서움 |
| 막히는 곳 | **무엇을 확인해야 하는지 모른다.** 이월결손금이 무엇인지, 임대 소득에서만 빠지는지 |
| 필요한 도움 | 1분 설명, "나는 해당될까?" 자가 점검 질문(결손이 났던 해가 있는가, 장부를 썼는가) |
| R1 | 마법사 0단계(설명과 그림, 하는 일/하지 않는 일). **"해당 여부 빠른 점검"은 없음 → Phase 2 후보** |

### 단계 2. 신고 이력을 모은다 (수집)

| 항목 | 내용 |
|---|---|
| 하는 일 | 홈택스에서 종합소득세 신고 내역을 조회하고 연도별 신고서를 연다/PDF로 받는다 |
| 막히는 곳 | ① 조회 기간이 **한 번에 최대 1년**이라 여러 번 조회해야 함 ② 한 해에 **정기·수정·경정청구**가 여러 건 → **어느 것이 최신/최종인지** 헷갈림 ③ 세무서가 결정을 바꾼 신고는 당초와 달라 보임 ④ 메뉴 이름이 여러 곳(세금신고내역, 신고서 조회, 전자신고 접수증)에 흩어져 있음 |
| 필요한 도움 | 경로 안내(정확한 메뉴 이름), 연도별 "최종본 고르는 법", 조회 체크리스트(연도×신고 종류) |
| R1 | 마법사 2단계(신고서 여는 법)와 해별 "어디서 찾나요?". **신고 이력 타임라인 정리, 최종본 판별은 없음 → Phase 2 후보(수동 입력 표 → PDF 읽기 순)** |

### 단계 3. 연도별 값을 정리한다 (입력·정리)

| 항목 | 내용 |
|---|---|
| 하는 일 | 연도마다 소득(결손), 신고서의 이월결손금 공제액·잔액을 표로 정리한다 |
| 막히는 곳 | ① **"임대업 줄"과 "임대업 외 줄"을 혼동**(칸 번호 3번/4번 등) ② 결손의 부호(음수)와 소득금액 정의(공제 전) ③ 명세서에 **자기 연도 행만** 있고 앞 해 잔액이 안 적힌 신고서 ④ 같은 해인데 신고서마다 **숫자가 다름**(오기, 수정 전후) ⑤ 입력할 값을 못 찾음 |
| 필요한 도움 | 줄 위치를 보여 주는 가상 서식 그림, 값이 없어도 진행("모르겠어요"), 입력 확인 단계(부호·연도), **서로 다른 숫자가 나왔을 때 무엇을 믿을지 안내** |
| R1 | 마법사 3~4단계(해별 입력, 입력 확인). **숫자 불일치(같은 해 여러 값) 입력과 비교는 없음 → Phase 2 후보** |

### 단계 4. 어긋난 해를 찾는다 (진단)

| 항목 | 내용 |
|---|---|
| 하는 일 | 발생액에서 공제액을 빼며 잔액이 어떻게 넘어가는지 따라간다. 처음 어긋난 해를 찾는다 |
| 생각·감정 | 계산이 복잡하고 자신이 없음. "내가 맞게 하는 건가?" → 어긋남을 발견하면 놀람·흥분, 곧 "정말 맞나?" 의심 |
| 막히는 곳 | 오래된 결손부터 공제하는 순서, 공제 가능 기한, 소득 한도, **앞 해 오류가 뒤 해에 계속 번짐**(첫 오류가 어디인지) |
| 필요한 도움 | 흐름표(해별 계산 vs 신고서), "여기부터 확인" 표시, 근거 계산 |
| R1 | **결과 화면(흐름표, 첫 어긋난 해, 경고 R-1~R-6).** 순서 위반(R-4)은 입력 부족으로 미구현 |

### 단계 5. 확정하고 요건을 확인한다 (판단 준비)

| 항목 | 내용 |
|---|---|
| 하는 일 | 앞서 낸 수정·경정청구가 **인정되었는지** 확인해 확정값을 정한다. 장부 보관·기한·승인 여부 등 요건을 점검한다 |
| 막히는 곳 | ① 승인 결과 확인 위치(결정 통지서, 신고내역) ② **기한**(청구는 법정신고기한 후 5년 `[확인 필요]`, 이월 기한 10/15년 `[확인 필요]`) ③ 추계신고였는지·장부를 보관했는지 ④ "청구해도 되나?"라는 판단 불안 |
| 필요한 도움 | 점검 질문(예·아니오·모르겠어요 + 확인 위치), 기한 계산 도우미, **세무사에게 확인할 질문 목록 만들기** |
| R1 | 확인 방법 안내만(점검 질문 6개는 2026-11-02에 PRD에서 뺌). **요건 점검(승인 여부, 장부 보관, 기한)은 없음 → Phase 2 후보** |

### 단계 6. 얼마나 달라지는지 가늠한다 (영향)

| 항목 | 내용 |
|---|---|
| 하는 일 | 공제를 추가하면 과세표준·세액이 얼마나 줄고 환급이 얼마인지 계산한다. 지방소득세도 별도로 따져 본다 |
| 막히는 곳 | 세율표·누진공제, 이미 낸 세액과의 비교, **지방소득세는 따로 신청**, 환급 가산금 |
| 필요한 도움 | 참고용 추정(확정 아님 표시), 소득세와 지방소득세 구분 안내 |
| R1 | **미구현**("더 공제 가능했던 금액의 합"만 참고 표시). **환급 영향 추정은 Phase 2 후보(PRD §3.5, 세율표 필요)** |

### 단계 7. 범위와 순서를 정하고 입력값을 준비한다 (준비)

| 항목 | 내용 |
|---|---|
| 하는 일 | 이번에 청구할 것만 정하고(다른 쟁점은 나중에), 비슷한 시기의 납부 일정이 있으면 순서를 정한다. 홈택스 입력 순서대로 값을 정리한다 |
| 막히는 곳 | 쟁점이 얽힘(예: 다른 항목을 건드리면 영향이 커짐), **납부 일정과 청구의 선후**, 입력값을 화면 순서와 맞춰 옮기는 일이 번거롭고 실수하기 쉬움 |
| 필요한 도움 | "이번에 하지 않을 것" 선택, 일정 체크(중간예납 등), **홈택스 입력 순서 시트 자동 생성** |
| R1 | **요약과 확인 방법 안내만.** 입력 순서 시트 생성은 Phase 2 후보(장부선생 변환 쪽 "홈택스 입력값" 기능을 이어 쓸 수 있음) |

### 단계 8. 제출하고 마무리한다 (실행·사후)

| 항목 | 내용 |
|---|---|
| 하는 일 | 홈택스에서 경정청구 작성 → 이월결손금명세서 입력 → 세액 자동 계산 확인 → **청구 이유 선택** → 환급계좌 → 제출 → 부속서류 제출 → 접수증 저장 → 지방소득세 환급 신청 → 결과 확인 → 다음 해 이월 잔액 기록 |
| 막히는 곳 | ① **청구 이유 드롭다운**(분류·항목 선택이 헷갈림) ② **제출 오류**가 나도 원인이 모호 ③ 첨부서류 종류(발생 연도 신고서, 앞선 결정 서류)와 PDF 요건 ④ 지방소득세는 **다른 사이트에서 별도 신청** ⑤ 결과까지 기다림, 언제 확인할지 ⑥ 다음 해 신고에 잔액을 어떻게 넘기는지 |
| 필요한 도움 | 화면별 입력 안내(실제 화면 용어), 청구 이유 선택 도우미, 제출 전 체크리스트, **제출 후 할 일 목록**(접수증, 지방소득세, 결과 확인 시기, 다음 해 잔액) |
| R1 | 확인 방법 안내(경로, 첨부, 기한) 1차 문구만. **제출 오류 도움말, 청구 이유 도우미, 사후 할 일 추적은 Phase 2 후보** |

## 4. 감정 곡선 (실제 경험 기반)

| 단계 | 1 의심 | 2 수집 | 3 정리 | 4 진단 | 5 확정·요건 | 6 영향 | 7 준비 | 8 실행·사후 |
|---|---|---|---|---|---|---|---|---|
| 감정 | 불안 | 피곤함 | 혼란(숫자 불일치) | **발견의 놀람**, 이어서 의심 | 조심스러움 | 기대 | 부담, 완벽주의 | 긴장(제출), 안도, 기다림 |
| 이탈 위험 | 중 | **높음**(최종본 구분) | **높음** | 중 | **높음**(판단 불안) | 낮음 | 중 | **높음**(오류·별도 사이트) |

이탈이 큰 곳은 단계 2·3·5·8이다. Phase 2는 이 네 곳을 먼저 덜어 주는 쪽이 효과가 크다.

## 5. R1이 덮는 범위와 Phase 2 후보

> Phase 2 첫 번째로 **신고 이력 정리표와 최종본 판별 도우미**를 PRD로 만들었다: [PRD-refund-history.md](PRD-refund-history.md)

| 저니 단계 | R1 | Phase 2 후보 (우선순위 제안) |
|---|---|---|
| 1 의심 | 설명·그림 | 해당 여부 빠른 점검(질문 3~4개). **낮음** |
| 2 수집 | 신고서 여는 법 | **신고 이력 정리표 + 최종본 판별 도우미**(연도×종류 표, 수동 입력). **높음** → 이후 PDF 읽기 검토 |
| 3 정리 | 해별 입력 | **같은 해 여러 값 비교(불일치 표시)**, 값 찾기 사례 보강. **높음** |
| 4 진단 | 흐름표, R-1~R-6 | R-4(순서 위반), 발생연도별 공제 내역 입력. 중간 |
| 5 확정·요건 | 확인 방법 안내(점검 질문은 뺌) | **기한 계산 도우미, 승인 여부 확인 흐름, 세무사 질문 목록 만들기.** 높음 |
| 6 영향 | 합계 참고 | **환급 영향 추정(세율표, 소득세/지방소득세 구분).** 중간(세율값·표현 확인 필요) |
| 7 준비 | 요약 | **홈택스 입력 순서 시트 자동 생성**(경정청구 화면 순서). 높음 |
| 8 실행·사후 | 확인 방법 | **청구 이유 선택 도우미, 제출 전 체크리스트, 오류 도움말, 제출 후 할 일 추적(접수증, 지방소득세, 결과 확인일, 다음 해 이월 잔액).** 높음 |
| 이후 | — | 이월 잔액을 **장부선생 변환(다음 해 복식부기 신고)** 입력으로 바로 넘기기 |

## 6. 설계 원칙 (원본 경험에서 얻은 것)

1. **한 번에 하나**: 사용자는 서류, 계산, 판단을 동시에 하다 지친다. 한 화면에 한 가지(R1과 같은 방식).
2. **모르는 것을 허용**: 값을 못 찾아도 진행하고, 못 찾은 부분은 "점검 불가"로 표시해 되돌아오게 한다.
3. **어디서 찾는지가 계산보다 어렵다**: 서류 이름과 줄 위치를 가장 공들여 안내한다(가상 서식 그림).
4. **첫 어긋난 해를 짚는다**: 오류는 뒤 해로 번진다. 가장 오래된 어긋난 해부터 보게 한다.
5. **범위를 좁히게 돕는다**: 쟁점을 한꺼번에 건드리지 않고 "이번에는 이것만"을 고르게 한다.
6. **판단은 사용자와 세무사**: 청구 여부와 금액을 정해 주지 않는다. 확인할 곳과 질문을 준다.
7. **끝난 뒤가 더 길다**: 제출은 절반이다. 접수증, 지방소득세, 결과 확인, 다음 해 잔액까지 할 일 목록으로 이어 준다.
8. **개인 정보는 밖으로 나가지 않는다**: 입력값은 브라우저 안에서만(서버 전송 없음), 이름·주민번호·계좌 입력칸 없음.

## 7. 법적·윤리 주의 (Phase 2 설계 때 지킬 것)

- 개별 신고서를 분석해 "청구하세요"라고 말하는 순간 세무 상담·대리에 가까워질 수 있다 `[확인 필요]`. 문구는 "다릅니다/확인해 보세요/세무사에게 문의"로 둔다.
- 환급 추정은 반드시 "참고, 확정 아님"으로 표시한다. 성공보수는 받지 않는다.
- PDF 자동 읽기를 도입하면 주민번호·주소·계좌가 포함된 문서를 다루게 된다. **브라우저 안에서만 처리하고 해당 값은 버리는 방식**이 아니면 하지 않는다.
- 홈택스 화면 이름과 서식 번호는 바뀐다. 안내 문서에 확인일을 적고 신고 시즌 전에 점검한다.

## 8. Phase 2에서 검증할 가설

1. 사용자의 이탈이 가장 큰 곳은 단계 2(최종본 구분)와 단계 8(제출 오류·별도 사이트)이다.
2. "신고 이력 정리표 + 불일치 표시"만으로도 R1 사용자의 대부분이 단계 3~4를 끝낸다.
3. 홈택스 입력 순서 시트를 자동으로 만들어 주면 제출 오류와 문의가 줄어든다.
4. 이용권 구매 동기는 **"내 값으로 결과를 본다"**(R1)보다 **"입력 시트와 제출 후 할 일까지 받는다"**(Phase 2)가 더 크다.
5. 측정: 단계별 완료율(마법사 단계 이탈), 모름 선택 비율, 결과 화면 도달률, 저장 파일 불러오기 비율(재방문). 단 서버로 개인 정보를 보내지 않는 방식으로만 측정한다(집계 가능한 수치만, 설계 필요).

## 9. 열린 질문

1. 가족(페르소나 B)의 대리 접근에서 홈택스 로그인과 위임이 어떻게 되는지, 도구가 어디까지 안내해도 되는지.
2. 경정청구 화면의 청구 이유 선택 안내를 어느 수준까지 구체화할지(세무사 확인 필요).
3. PDF 자동 읽기의 현실성(홈택스 PDF 서식 변동, 브라우저 안 처리 성능, 개인정보 마스킹).
4. 환급 추정을 넣을 때의 세율 값 관리(연도별 세율표 파일, 확인 책임).
5. 사후 할 일 추적을 어떻게 저장할지(서버 없이 파일 저장만으로 충분한지, 알림이 필요한지).
