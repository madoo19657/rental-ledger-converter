- 상태: 초안 v0.1
- 작성일: 2026-11-01
- 범위: 환급 점검(R1)에서 사용자가 겪는 **가장 큰 이탈 지점**인 "내 신고 이력이 여러 건인데 어느 신고서가 기준인지 모르겠다"를 풀어 주는 기능. 사용자 저니의 **단계 2(수집)와 단계 3(정리)** 에 해당한다.
- 관련 문서: [user-journey-refund.md](user-journey-refund.md)(저니와 Phase 2 후보), [PRD-refund-check.md](PRD-refund-check.md)(R1, 이 기능이 붙는 곳), [PRD-paid-license.md](PRD-paid-license.md)(이용권·서버 배포 구조)
- 이 문서에는 개인 금액·접수번호·실제 신고일이 없다. 실제 사례의 세부는 볼트 `source-docs/hometax-filing-history.md`에만 있고, 실제 사례 테스트는 `tests-private/`에 둔다.
- **법령·홈택스 화면은 직접 확인하지 못했다.** 확인이 필요한 부분은 `[확인 필요]`로 표시했다. 세무 상담이 아니다.

## 0. 결정할 것과 가정

| 항목 | 가정 (이 문서의 기본값) |
|---|---|
| 위치 | R1 마법사에 **선택 단계**로 끼운다(신고서 여는 법 다음, 해별 입력 앞). "이미 값을 아는 사용자는 건너뛰기" 허용 |
| 입력 방식 | ① **직접 입력 표**(항상 가능) ② **홈택스 목록 붙여넣기** ③ **홈택스 엑셀 내려받기 파일 읽기**. ②③은 실제 형식을 확인한 뒤 H2에서 만든다 |
| 출력 | 연도별 **기준 신고서 후보와 이유**, 확인 필요 표시, **받아야 할 서류 체크리스트**, 연도 간 영향 경고 |
| 판단 | 도구는 **후보와 근거만** 보여 준다. 확정은 사용자(필요하면 세무사)가 한다 |
| 개인정보 | 입력은 브라우저 안에서만. 이름·주민번호·주소 열은 **읽지 않고 버린다**. 접수번호는 사용자가 원할 때만 보관 |
| 요금 | R1과 같은 이용권에 포함(별도 요금 미정, 열린 질문) |

## 1. 배경과 문제

실제 경험에서 이 단계가 가장 오래 걸렸다.

- 한 귀속연도에 **정기신고, 수정신고, 경정청구가 여러 건** 섞여 있다(수정신고가 연이어 3번인 해도 있었다).
- 목록은 **여러 화면**(세금신고내역의 탭 3개, 전자신고 접수증·납부서 출력, 환급금 상세조회)에 나뉘어 있고, 화면마다 조회 기간 제한이 다르다.
- **경정청구는 "요청"이다.** 접수됐다고 해서 반영된 것이 아니고, 승인·거부·일부 인정은 다른 곳(결정 통지, 환급 내역)에서 확인해야 한다.
- **연도 사이에 순서 문제**가 생긴다. 뒤 해 신고서가 앞 해의 수정보다 **먼저 접수**되었다면, 뒤 해 신고서의 이월결손금 칸은 수정 전 값일 수 있다. 사용자는 이 점을 스스로 알아채기 어렵다.
- 오래된 해의 원 신고는 조회 기간 밖이라 **목록에 아예 없다**.
- 같은 청구를 **두 번** 낸 흔적(같은 연도, 같은 청구세액)이 있으면 어느 쪽이 유효한지 불분명하다.

결과적으로 사용자는 "이 해의 어느 신고서를 열어야 맞는지" 모른 채 값을 옮겨 적고, R1 점검이 **틀린 입력으로 틀린 경고**를 내게 된다. 입력의 근거 자체를 먼저 정리해야 한다.

## 2. 목표와 비목표

### 목표
1. 연도별 신고 이력을 한 표로 모은다(구분, 접수일, 상태).
2. 연도마다 **기준 신고서 후보와 그 이유**를 보여 주고, 확신이 서지 않는 이유(경정청구 결과 미확인, 같은 날 복수, 목록 밖 등)를 **확인 필요**로 표시한다.
3. **연도 간 순서 문제**(뒤 해 신고서가 앞 해 수정보다 먼저 접수됨)를 찾아 알린다.
4. 어떤 신고서 PDF를 **받아야 하는지** 최소 목록으로 줄인다(연도별 기준 신고서와 확인용 서류).
5. 결과를 R1 입력 화면에 연결해, 해별 입력 때 "이 해는 ○○ 신고서를 보세요"를 보여 준다.

### 비목표
- 홈택스 자동 연동, 로그인, 크롤링.
- 신고서·결정통지서 PDF 자동 읽기(후속, H4).
- 경정청구의 승인 여부를 **추정해서 확정**하는 일. 사용자가 확인한 결과를 받아 쓴다.
- 세액·환급액 계산(R1·Phase 2의 다른 기능).
- 세무 대리·상담.

## 3. 사용자와 시나리오

| 페르소나 | 상황 |
|---|---|
| A. 직접 신고하는 임대사업자 | 이력 14건 안팎, 수정신고가 여러 번. "어느 것이 최신인가"가 불안 |
| B. 가족 신고를 정리해 주는 사람 | 부모님 이력을 여러 번 나눠 조회 |
| C. 신고만 끝내고 점검받고 싶은 사람 | 이력이 단순(해마다 정기신고 1건). 최종본 판별이 쉽지만 연도 간 순서만 확인하고 싶음 |

**핵심 시나리오**
1. 사용자가 R1에서 "신고서 여는 법"을 보고, 이어서 "신고 이력 정리"를 연다.
2. 홈택스 목록을 붙여넣거나(또는 엑셀 파일을 올리거나) 직접 입력한다.
3. 연도별 카드가 나오고, 각 카드에 "기준 신고서: 2024-05-12 수정신고" 같은 후보와 "확실/확인 필요"가 표시된다.
4. 경정청구가 있는 해에서는 "승인 여부를 확인했나요?"를 묻고, **확인하는 방법**(어디서 보는지)을 안내한다.
5. 경고(연도 간 순서, 목록 밖, 중복 청구)를 확인한 뒤 "받을 서류 체크리스트"로 신고서를 받는다.
6. R1의 해별 입력 화면으로 넘어가면 각 해에 "이 해는 이 신고서를 보세요"가 붙어 있다.

## 4. 기능 요구사항

### 4.1 입력

**레코드(한 행 = 신고 한 건)**

| 필드 | 설명 | 필수 |
|---|---|---|
| 귀속연도 | 어느 해 소득의 신고인가 | 예 |
| 접수일 | 신고·청구를 접수한 날 | 예 |
| 구분 | 정기신고 / 수정신고 / 기한후신고 / 경정청구 / 세무서 결정(통지서만 있음) / 기타 | 예 |
| 경정청구 결과 | 승인 / 일부 인정 / 거부 / 진행 중 / 모름 (**구분이 경정청구일 때만**) | 경정청구면 예 |
| 청구세액(선택) | 경정청구서의 환급받을 세액. 중복 청구 판별에 씀 | 아니오 |
| 접수번호(선택) | 신고서 보기·문의용 | 아니오(기본 보관 안 함) |
| 서류 확보 | 이 신고서 PDF를 받았는가(체크) | 아니오 |
| 메모 | 자유 입력(개인정보 입력 금지 안내) | 아니오 |

**입력 방법**
1. **직접 입력 표**: 행 추가/삭제, 연도·접수일·구분 선택. 구분은 홈택스 화면의 이름 그대로 고르게 한다. 항상 제공.
2. **붙여넣기**(H2): 홈택스의 신고 목록을 복사해 붙여넣으면 행으로 나눈다. 인식하지 못한 줄은 그대로 보여 주고 직접 고치게 한다. 형식 변동에 대비해 **미리보기와 수정**을 거친다. `[확인 필요: 실제 복사 형식]`
3. **엑셀·CSV 읽기**(H2): "세금신고내역"의 엑셀 내려받기 파일을 올린다(홈택스에 엑셀 내려받기가 있음). 필요한 열(귀속, 접수일, 구분, 청구세액)만 읽고 **이름·주민번호·주소 등 나머지 열은 버린다.** `[확인 필요: 열 이름과 구성]`
4. 입력 화면에서 **조회 방법 안내**(어느 메뉴에서 어떻게 조회하나)를 함께 보여 준다. 화면마다 조회 기간 한도가 달라 여러 번 나눠 조회해야 한다는 점, 정기·수정·기한후 신고와 경정청구가 **서로 다른 탭**이라는 점, 환급 확인은 환급금 상세조회에서 한다는 점을 안내한다.

### 4.2 기준 신고서 판별 규칙

연도별로 아래 순서로 판단한다. 규칙은 **결정론적 코드**로 두고, 결과마다 **이유 문구**를 붙인다.

| 규칙 | 내용 |
|---|---|
| F1 후보 | 그 귀속연도의 정기·수정·기한후 신고, 세무서 결정, **승인(또는 일부 인정)된 경정청구**가 후보다. 거부된 경정청구는 후보에서 뺀다 |
| F2 기준 | 후보 중 **접수일이 가장 늦은 것**을 "기준 신고서 후보"로 한다 |
| F3 같은 날 복수 | 후보 중 접수일이 같은 것이 둘 이상이면 어느 쪽이 마지막인지 모르므로 **확인 필요**로 표시하고, 접수번호나 접수 시각을 확인하라고 안내한다 |
| F4 경정청구 결과 불명 | 진행 중·모름인 경정청구가 후보보다 **늦은 접수일**이면, 기준이 바뀔 수 있으므로 **확인 필요**로 표시하고 결과 확인 방법을 안내한다(결정 통지서, 환급금 상세조회, 신고내역의 처리 상태) |
| F5 이력 없음 | 점검 범위의 연도에 레코드가 없으면 "**목록에 없음**"으로 표시한다. 원인 후보: 조회 기간 밖 / 신고를 안 한 해 / 입력 누락. 기간을 넓혀 조회하거나 신고서를 직접 열어 보라고 안내한다. 이월결손금은 **그 해 신고서를 제출해야** 인정된다고 알려진 점을 함께 안내한다 `[확인 필요]` |
| F6 중복 청구 | 같은 귀속연도·같은 청구세액의 경정청구가 둘 이상이면 **확인 필요**: 뒤의 것이 앞의 것을 대신했는지, 하나만 처리됐는지 확인하라고 안내한다 |
| F7 세무서 결정 | 세무서가 직권으로 바꾼 결정은 신고 목록에 접수 건으로 나타나지 않을 수 있다 `[확인 필요]`. 사용자가 "결정 통지서를 받은 적이 있다"고 입력하면 레코드로 추가해 후보에 넣는다 |

**상태 표시**
- **확실**: 후보가 하나로 정해지고 F3·F4·F6에 걸리지 않음.
- **확인 필요**: F3·F4·F6 중 하나라도 해당(이유 표시).
- **목록 없음**: F5.
- 어느 경우에도 "이 신고서가 맞다"고 단정하지 않고 "기준으로 보세요"로 쓴다.

### 4.3 연도 간 영향 점검 (핵심)

이월결손금은 앞 해의 값을 이어받으므로 **신고서의 접수 순서**가 중요하다.

| 규칙 | 내용 |
|---|---|
| H-3 앞 해 수정 미반영 가능 | 연도 y의 기준 신고서 접수일보다 **늦은** 접수일의 앞 연도(x < y) 수정신고·승인된 경정청구가 있으면, y의 신고서는 그 수정 **이전 값**을 이어받았을 수 있다. 해당 y에 경고를 붙이고 "y의 이월결손금명세서를 다시 확인하세요, 앞 해 수정이 결손금·소득을 바꿨는지 확인하세요"로 안내한다 |
| H-3a 영향 여부 | 수정이 결손금·소득을 **바꾼 것인지**는 이력만으로는 모른다. "이 수정은 소득금액이나 결손금을 바꾼 것인가요? (예/아니오/모르겠어요)" 질문으로 받고, 아니오면 경고를 낮춘다 |
| H-3b 전파 | H-3에 걸린 해 이후의 해는 "앞 해 영향을 받을 수 있음"으로 표시한다(첫 해를 "먼저 확인"으로 짚음) |

실제 사례에서 이 규칙이 잡아야 했던 것: 뒤 해의 신고서가 앞 해들의 마지막 수정보다 먼저 접수되어, 뒤 해 신고서의 이월결손금 값이 최신이 아니었다.

### 4.4 출력

1. **연도별 카드**(시간 순): 귀속연도, 이력 건수, 기준 신고서 후보(구분·접수일), 상태(확실/확인 필요/목록 없음), 이유 한 줄, 경고 배지.
2. **타임라인 표**: 접수일 순으로 모든 레코드를 한 줄씩 보여 주고, 연도 간 순서 문제를 화살표나 강조로 표시한다.
3. **받아야 할 서류 체크리스트**: 연도별 기준 신고서(필수), 확인 필요한 해의 비교용 서류(직전 신고서 또는 결정 통지서). **체크하면 R1 해별 입력에서 "받음"으로 표시**한다.
4. **확인 질문**: 경정청구 결과, 수정이 소득을 바꿨는지, 결정 통지서 유무를 사용자에게 묻는 질문 목록(한 화면에 하나씩 또는 연도별 접힌 질문).
5. **요약 한 장**(인쇄/PDF): 세무사에게 보여 줄 용도. "이력 14건 중 확인 필요 N건" 같은 요약.
6. **저장**: R1의 "여기까지 저장" 파일에 함께 들어간다(서버 저장 없음).

### 4.5 R1과의 연결
- 마법사에 "신고 이력 정리" 선택 단계를 둔다. 건너뛰면 R1은 지금과 같이 동작한다.
- 정리했다면 R1 해별 입력 화면 위에 "**이 해는 [구분] [접수일] 신고서를 보세요**"와 확인 필요 이유를 보여 준다.
- R1 결과 화면에서 어긋난 해가 나오면, 그 해의 이력 경고(예: H-3)를 **원인 후보**로 함께 보여 준다.
- R1이 받은 값이 기준 신고서가 아닌 다른 신고서에서 읽은 값일 가능성(서류 확보 체크가 비어 있음)도 표시한다.

### 4.6 안내와 문구 규칙
- "이 신고서가 최종입니다"라고 쓰지 않는다. "기준으로 보세요, 이유는 ○○".
- 경정청구 승인 여부는 **사용자가 입력**한다. 도구가 추정하지 않는다.
- 모든 경고에 "확인 방법"(어느 메뉴에서 볼 수 있는지)을 붙인다. 메뉴 이름은 `docs/hometax-menu-map.md`·`hometax-usage-guide.md`를 단일 출처로 한다.
- 개인 식별 정보(이름, 주민번호, 주소)는 입력하지 말라고 입력 화면에 알린다.

## 5. 아키텍처

| 요소 | 구현 |
|---|---|
| 판별 모듈 | `src/history-check.js`(순수 함수): `analyzeHistory(records, { yearsInScope })` → 연도별 카드, 경고, 체크리스트. 정규화·열쇠 함수 포함 |
| 서버 배포 | R1의 유료 모듈 묶음(`scripts/build-server.js`)에 포함. 체험은 가상 이력을 빌드 때 미리 계산해 쓴다(R1과 같은 방식) |
| 파서(H2) | `src/history-parse.js`: 붙여넣기 텍스트와 xlsx/csv에서 필요한 열만 추출. 이름·주민번호 등은 읽자마자 버린다 |
| 화면 | `src/refund-wizard.js`에 단계 추가(입력 표, 연도별 카드, 체크리스트). 표 입력은 모바일에서 카드형으로 |
| 규칙 값 | 규칙은 코드에 두되, **용어(구분 이름)와 화면 경로 문구**는 `config/history-terms.json`에 모아 확인일을 적는다 |
| 테스트 | 공개: 가상 이력 시나리오(아래 7장). 비공개: 실제 사례 이력(`tests-private/`)에서 기대 결과(기준 후보, 경고 종류)만 검증 |
| 저장 | R1 저장 파일(JSON)에 `history` 키 추가. 서버 전송 없음 |

## 6. 법적·윤리적 제약
- 개별 신고 이력을 보고 어느 서류가 유효한지 알려 주는 일은 **세무 상담**과 가까울 수 있다 `[확인 필요]`. 도구는 규칙에 따른 **후보와 확인 방법**만 제공하고, 단정하지 않는다. 문구와 서비스 형태는 R0(세무사 확인)에 포함한다.
- 접수번호는 신고서를 찾는 열쇠이므로 개인 정보로 취급한다. 기본은 보관하지 않고, 사용자가 원하면 저장 파일에만 넣는다.
- 붙여넣기·엑셀 파서는 **필요한 열 외에는 메모리에서도 버린다.** 오류 보고나 로그에 입력 원문을 남기지 않는다.
- 홈택스 화면·용어는 바뀐다. `config/history-terms.json`에 확인일을 적고 신고 시즌 전에 점검한다.

## 7. 수용 기준

1. 가상 이력(한 해에 수정신고 여러 번, 경정청구 승인·거부·진행 중 혼합, 같은 날 2건, 같은 청구세액 2건, 목록 없는 해)에서 **F1~F7이 기대한 상태와 이유**를 낸다(단위 테스트).
2. 뒤 해 신고서가 앞 해 수정보다 먼저 접수된 가상 이력에서 **H-3 경고가 그 뒤 해에 붙고**, 그 이후 해는 전파 표시가 된다. 수정이 소득을 바꾸지 않았다고 답하면 경고가 낮아진다.
3. 거부된 경정청구는 후보에서 빠지고, 진행 중·모름은 "확인 필요"가 된다.
4. 실제 사례 이력(비공개 테스트)에서 **기준 후보와 경고 종류가 사용자가 직접 정리한 결과와 일치**한다(오탐은 이유 문구로 설명 가능해야 함).
5. 어떤 경우에도 "최종본입니다"라고 단정하는 문구가 없다(문구 검사 테스트).
6. 입력 표는 키보드와 휴대폰에서 쓸 수 있고, 이름·주민번호 열은 파서가 읽지 않는다(파서 테스트).
7. 정리 단계를 건너뛰어도 R1이 지금과 같이 동작한다. 정리했다면 해별 입력에 기준 신고서 안내가 나온다.
8. 사용성(비공개 시험, 가상 이력): 홈택스 목록을 처음 보는 사람이 안내만 보고 이력을 입력하고 기준 신고서 후보를 설명할 수 있다(5명 중 4명).

## 10. 성공 지표
- 이력 정리 단계 **완료율**(시작 대비 완료), **건너뛰기 비율**.
- 이력 정리를 한 사용자의 R1 **결과 도달률**과 "모름" 선택 비율(정리하지 않은 사용자와 비교).
- "확인 필요" 표시 후 사용자가 **이유를 읽고 조치한 비율**(서버에 개인정보를 보내지 않는 집계만).
- 사용성 시험의 평균 입력 시간(목표: 연도 5개 이력을 10분 안).

## 11. 열린 질문
1. 홈택스 목록 붙여넣기 형식이 안정적인가. 엑셀 내려받기의 열 이름은 무엇인가(H0에서 확인).
2. 세무서 직권 결정과 경정청구 결과를 사용자가 쉽게 확인하는 가장 좋은 화면은 어디인가.
3. 이력 정리를 R1과 **분리한 독립 기능**(무료 일부 공개)으로 둘지. 블로그 유입 도구로 쓸 수 있다.
4. 접수번호를 저장 파일에 넣을지 기본값(보관 안 함 vs 선택 보관).
5. 요금: R1 이용권에 포함할지, 과거 연도용 별도 이용권(PRD-refund-check §9-1)과 묶을지.
6. 가족(페르소나 B)의 이력을 한 파일에 여러 명 담을 수 있게 할지(사람별 구분이 필요).
