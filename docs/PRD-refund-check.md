## 0. 결정 사항 (2026-11-01, 사용자)

| 항목 | 결정 |
|---|---|
| 방향 | "신고서를 분석해 경정청구를 대신해 주는 서비스"가 아니라, **부동산 임대소득 이월결손금 점검 도구**로 좁혀 시작한다 |
| 제품 위치 | 별도 제품이 아니라 **장부선생 안의 기능**("환급 점검")으로 둔다 (이름·이용권·서버 공유) |
| 순서 | ① 이월결손금 추적기 → ② 경정청구 입력값 출력 → ③ 후속으로 PDF 자동 읽기 (점검 질문 목록은 2026-11-02에 뺐다) |
| 입력 방식 | 연도별 **직접 입력**(5~6개 값). PDF 자동 읽기는 하지 않는다 |
| 사업 형태 | **정액 이용권**. 환급액에 비례하는 성공보수는 받지 않는다 |
| 진행 방식 | 초보자도 따라 할 수 있도록 **단계별 마법사**로 진행한다. **한 단계를 마치면 다음 화면으로** 넘어간다(§3.0) |

## 1. 배경과 목표

- 간편장부로 신고하다 복식부기로 바꾸거나 결손이 난 해가 있는 임대사업자는 **이월결손금이 해마다 이월**된다. 한 해에 오류(결손 누락, 공제 누락, 잘못된 소멸 처리)가 생기면 뒤 연도가 모두 틀어지는데, 당사자가 알아채기 어렵다.
- 이 프로젝트의 실제 사례가 그랬다. 결손금이 신고서에 반영되지 않았거나 잘못 적혀 있어서, 연도별 흐름을 한 장으로 맞춰 보고서야 발견했고 환급 청구로 이어졌다.
- 목표
  1. 연도별 이월결손금의 **발생·공제·잔액·소멸**을 계산해 보여 주고, 신고서에 적힌 값과 **어긋나는 해**를 짚는다.
  2. 어긋남이 있으면 **어디를 어떻게 확인할지** 홈택스 메뉴와 필요한 값을 안내한다. 청구 여부와 금액의 판단은 사용자와 세무사가 한다.
- 성공의 모양: 이용자가 연도별 값을 10분 안에 입력하고, "이 해를 확인해 보세요"라는 구체적인 신호와 근거 계산을 얻는다.

### 비목표 (v1)
- 경정청구서 제출 대행, 환급액 보장·확정 표시, 성공보수.
- 신고서·결정통지서 PDF 자동 읽기, 홈택스 자동 연동.
- 근로소득 연말정산, 양도소득, 주택임대 등 임대업 외 소득의 점검.
- 세무 상담. 개별 상황에 대한 "청구하세요" 같은 지시.

## 2. 사용자와 시나리오

| 사용자 | 상황 | 필요 |
|---|---|---|
| 임대사업자(주로 본인 신고) | 과거에 결손이 났거나 장부 방식을 바꿨음. 신고서 값이 맞는지 모름 | 연도별 흐름 점검 |
| 이미 장부선생을 쓰는 사용자 | 복식부기로 바꾸며 과거 결손금이 제대로 넘어갔는지 궁금 | 변환 결과와 이어서 점검 |
| 가족 신고를 도와주는 사람 | 부모님 신고서를 대신 정리 | 여러 사람 값을 따로 점검 |

핵심 시나리오
1. 체험: 가상 시나리오(몇 해에 걸쳐 결손이 나고 한 해 공제가 빠진 예)를 불러와 어긋난 해가 표시되는 것을 본다.
2. 유료: 내 값을 연도별로 입력 → 계산 흐름과 어긋난 해 확인 → "확인 방법" 안내 → 세무사 또는 홈택스에서 확인.

## 3. 기능 요구사항

### 3.0 진행 방식: 단계별 마법사 (사용자 요구, 2026-11-01)

한 화면에 모든 것을 늘어놓지 않고, **한 화면에 한 가지 일만** 시킨다. 그 일이 끝나면 "다음"이 열리고 다음 화면으로 넘어간다. 장부선생의 기존 변환 화면(한 페이지에 1~4단계)과 달리 환급 점검은 **화면 전환형**이다.

| 단계 | 화면의 일 | 끝나는 조건 (다음 버튼이 열림) |
|---|---|---|
| 0 | 이월결손금 설명(1분), 이 점검이 하는 일과 하지 않는 일, 체험/내 값 선택 | 선택함 |
| 1 | 점검할 해 정하기 (어느 해부터 어느 해까지, 모르면 안내) | 시작·끝 연도 정함 |
| 2 | 홈택스에서 신고서 여는 법 (경로 안내, 연습 체크리스트) | "열었어요" 확인 |
| 3-n | **한 해씩** 입력 (3개 값, 찾는 법 도움말). 해마다 같은 화면을 반복 | 그 해 값을 넣었거나 "값을 못 찾았어요" 선택 |
| 4 | 입력 확인 (연도별 요약, 부호·연도 재확인) | "맞아요" 확인 |
| 5 | 결과: 연도별 흐름 표와 어긋난 해 | 결과를 봄(자동) |
| 6 | 확인 방법·준비할 값 안내 (경정청구 준비 가이드) | 읽음 |
| 7 | 요약 저장·인쇄, 세무사 확인 권장 안내 | 끝 |

**규칙**
- 맨 위에 **진행 표시**(현재 단계 / 전체 단계, 남은 해 수)를 항상 보인다. 다음 버튼 글자는 "다음: ○○"처럼 **다음에 할 일**을 쓴다.
- **뒤로**와 "이 단계 다시 하기"가 항상 있다. 앞 단계 값을 바꾸면 뒤 결과가 자동으로 다시 계산되고, 영향받는 단계에 표시한다.
- 단계 안에서 막히면 **건너뛰기가 아니라 "모르겠어요"** 를 고른다. 그러면 그 값을 비운 채 진행하되, 결과에서 "점검 불가"로 표시한다(§3.1-1).
- 진행 상태는 **브라우저 안에서만** 유지하고, 중간에 닫을 때를 위해 "여기까지 저장"을 파일로 내려받게 한다(서버 저장 없음). 불러오면 마지막 단계로 돌아온다.
- 휴대폰에서도 한 손으로 쓸 수 있게 **한 화면에 한 가지, 큰 버튼, 세로 스크롤 최소**. 키보드(Enter=다음, 뒤로가기)와 스크린 리더(단계 변경 시 제목 읽기)를 지원한다.
- 입력이 많은 해 반복(3-n)은 **연도 목록과 진행률**(예: 3/6년)을 보여 주고, 이미 입력한 해는 "수정" 링크로 돌아갈 수 있다.
- 체험 모드는 같은 마법사를 가상 시나리오 값으로 끝까지 보여 준다(값은 읽기 전용, 단계는 실제와 동일).

### 3.1 입력 (연도별, 직접 입력)
| 항목 | 설명 | 비고 |
|---|---|---|
| 귀속연도 | 점검할 해 | 시작·끝 연도 선택 |
| 결손금 발생액 | 그 해 부동산임대업 소득금액이 음수일 때 그 금액 | 신고서·소득금액 조정 결과에서 |
| 신고서의 이월결손금 공제액 | 신고서에 적힌 공제액 | 없으면 0 |
| 신고서의 이월결손금 잔액 | 있으면(선택) | 대조용 |
| 부동산임대업 소득금액 | 그 해 소득금액(공제 전) | 공제 한도 계산에 필요 |
| 종합소득 과세표준(선택) | 환급 영향의 대략 추정용 | 비워도 됨 |
| 신고 방식(선택) | 간편장부·복식부기, 수정신고 여부 | 안내 문구 분기 |

- 이름, 주민등록번호, 주소, 계좌는 **입력칸을 두지 않는다.** 안내 문구로 입력하지 말라고 알린다.
- 입력값은 브라우저 안에서만 쓴다. 서버로 보내지 않는다(PRD-paid-license의 원칙 그대로).
- "입력값 저장"은 파일로만(장부선생의 기존 저장 기능과 같은 방식).

### 3.1-1 입력 도우미: 값을 어디서 찾는지 알려 준다 (사용자 요구, 2026-11-01)

대부분의 사용자는 이월결손금이 **무엇이고 어느 서류의 어느 칸에 있는지** 모른다. 입력 화면의 가장 중요한 일은 계산보다 **"찾는 법 안내"**다.

**원칙**
- 모든 입력칸에는 "어디서 찾나요?"가 붙는다(펼침). 용어는 쉬운 말로 먼저 설명하고 서류 이름은 그 뒤에 쓴다.
- 칸 이름은 신고서·홈택스 화면에서 보이는 이름과 **같은 이름**을 병기한다(예: 사용자 말 "지난해까지 넘어온 결손" ↔ 서류 이름 "이월결손금").
- 값을 모르면 **비워 둬도 진행**된다. 비운 칸은 "이 해는 값이 없어 점검하지 못함"으로 표시하고, 어디서 찾는지 다시 안내한다.
- 예시 값을 자동으로 채우지 않는다(샘플 시나리오는 별도 모드). 실제 사용자의 화면 캡처는 쓰지 않고 **가상 서식 그림**을 쓴다.

**구성**
1. **이월결손금이 뭔가요? (1분 설명)** 결손이 난 해의 금액이 다음 해들로 넘어가 소득에서 빼지는 흐름을 그림으로(발생 → 공제 → 잔액 → 소멸 기한). 부동산임대업(주택 제외)만 해당한다는 점과 "임대 소득이 있는 해에만 빠진다"는 점을 함께 알린다. 세법 내용은 `[확인 필요]` 표시.
2. **어느 해를 봐야 하나요?** 결손이 난 가장 오래된 해부터 최근 해까지. 언제 결손이 났는지 모르면 "최근 5~6년 신고서를 차례로 열어 보세요"로 안내하고, 홈택스에서 신고 내역을 조회하는 방법(조회 기간이 한 번에 최대 1년이라 나눠 조회)을 설명한다.
3. **신고서를 여는 방법(홈택스)**: `세금신고 > 신고서 조회/삭제/부속서류 > 전자신고 접수증·납부서 출력`에서 세목을 종합소득세로 고르고 기간을 넣어 조회 → 목록의 접수번호(신고서보기)로 신고서를 연다. 경정이 있었다면 `나의 홈택스 > 세금신고내역`의 경정청구 탭과 결정 통지 내용도 확인한다. (경로는 `docs/hometax-usage-guide.md`·`docs/hometax-menu-map.md` 기준이며, 화면 이름이 바뀔 수 있어 정기 확인한다 — 리스크 §8.)
4. **서류에서 값 찾기(가상 서식 그림 + 칸 번호)**
   - 결손금 발생액: 그 해 소득금액(조정계산서 결과)이 **음수**인 해의 금액. 신고서의 "결손금·이월결손금공제명세서"에서 발생 과세기간별로 확인한다.
   - 이월결손금 공제액: 같은 명세서에서 **부동산임대업(주택임대업 제외)** 줄의 공제금액. 임대업 외 줄과 헷갈리지 않도록 줄 위치를 그림으로 표시한다.
   - 부동산임대업 소득금액: 신고서의 사업소득명세서/조정계산서 값.
   - 서류 이름과 칸 번호는 세무사 검수를 거친 뒤 확정한다.
5. **한 해씩 입력(마법사 3-n단계)**: 연도 하나를 고르면 "이 해 신고서를 열고, 아래 3개 값을 찾아 적으세요"로 해당 연도에 필요한 칸만 보여 준다. 한 화면에 모든 연도를 표로 늘어놓는 입력은 고급 보기로 둔다.
6. **막혔을 때**: "신고서 PDF에서 그 칸이 안 보여요 / 0으로 적혀 있어요 / 명세서 자체가 없어요"를 각각 안내한다. 명세서가 없고 결손이 있었던 해는 그 자체가 점검 신호(R-1)임을 알려 준다.
7. **입력 확인 단계**: 다 적은 뒤 입력한 값을 요약해 보여 주고 "부호(음수)와 연도가 맞는지" 한 번 더 묻는다.

**사용성 목표(수용 기준 9·10 참조)**: 이월결손금을 처음 들어 본 사람이 안내만 보고 연도 하나를 입력하는 데 걸리는 시간 5분 이내.

### 3.2 계산 규칙 (가정, 판매 전 세무사 확인)
- 임대업 결손금은 **그 해 부동산임대업 소득에서만** 공제하고, 발생 연도가 **오래된 것부터** 공제한다 `[확인 필요]`.
- 공제 기한: 2018·2019년 발생분 10년, 2020년 이후 발생분 15년으로 알려져 있다 `[확인 필요]`. **연도별 규칙은 코드에 박지 않고 `config/loss-carryover-rules.json`에 두어** 확인 후 값만 바꾼다.
- 공제 가능액 = min(남은 이월결손금, 그 해 부동산임대업 소득금액 중 0 이상 부분).
- 결과: 연도별 [기초 잔액, 발생, 공제 가능액, 신고서 공제액, 차이, 기말 잔액, 소멸 예정 연도].

### 3.3 어긋남 점검 (경고 종류)
| 코드 | 내용 |
|---|---|
| R-1 | 결손이 발생했는데 다음 해 이후 신고서 공제액이 0이다(공제 누락 가능) |
| R-2 | 신고서 공제액이 계산한 공제 가능액보다 작다/크다 |
| R-3 | 기한이 지난 결손금을 공제했거나, 공제 가능한 기간인데 소멸 처리됐다 |
| R-4 | 오래된 결손금보다 새 결손금을 먼저 공제한 흔적(순서 위반) |
| R-5 | 신고서 잔액이 계산한 잔액과 다르다 |
| R-6 | 입력한 소득금액이 음수인데 결손금 발생액이 0이거나 반대(입력 확인 요청) |

- 모든 경고는 **"확인이 필요합니다"** 수준으로 표현하고, 근거 계산(어느 해의 어떤 값)을 함께 보인다.
- 경고가 없으면 "입력한 값 기준으로는 어긋남이 보이지 않습니다. 입력이 맞는지, 다른 공제 항목은 별도로 확인하세요"로 끝낸다. "문제없음"이라고 단정하지 않는다.

### 3.4 (삭제) 점검 질문 목록
2026-11-02 사용자 결정으로 점검 질문 단계(옛 6-n)를 이 PRD에서 뺐다. 결과 다음은 바로 "확인 방법"(§3.0 단계 6)이다. 질문 형식의 누락 항목 점검은 이번 범위가 아니다.

### 3.5 환급 영향 추정 (선택, 참고용)
- 과세표준을 입력한 경우에 한해, 결손금 공제가 달라질 때 **과세표준 변화와 세율표상 대략적 세액 차이**만 보여 준다. 환급액이 아니다.
- 표시 문구: "참고 추정입니다. 지방소득세, 가산금, 다른 공제, 국세청 결정에 따라 달라집니다."
- 이 기능을 v1에 넣을지는 열린 질문(§9).

### 3.6 출력
- 요약 한 장: 연도별 표, 어긋난 해, 확인 방법. 인쇄/PDF 저장.
- (R3) 경정청구를 직접 준비할 때 필요한 값 목록: 연도, 항목, 입력 위치(홈택스 메뉴 흐름은 `docs/hometax-menu-map.md`와 사용법 문서를 따른다). 청구서 문구를 자동 작성하지는 않는다.

### 3.7 화면과 이용권
- 장부선생 화면에 **"환급 점검" 진입 버튼**을 두고, 누르면 §3.0의 마법사 화면으로 들어간다(기존 변환 화면과 오가기 쉽게 머리글은 공유). 시작 선택은 단순하게 한다(체험 시나리오 / 내 값 입력).
- 체험: 가상 시나리오 전체 결과를 볼 수 있다. 계산 코드는 장부선생과 같은 방식으로 **유료 모듈로 서버에서만 내려주고**, 체험 결과는 빌드 때 미리 계산해 넣는다(PRD-paid-license §Phase 1b·체험 결과 화면 구조 재사용).
- 유료: 내 값 입력, 저장, 출력.

## 4. 법적·윤리적 제약

- 세무사법상 세무 대리·상담과 닿는 부분이 있을 수 있다 `[확인 필요: 법령 직접 확인 못함]`. 따라서 v1은 다음을 지킨다.
  - 정액 이용권. 환급액 연동 요금 없음.
  - 문구 규칙: "~하세요(청구하세요)" 대신 "~가 다릅니다. 확인해 보세요/세무사에게 문의하세요". 환급·결과를 보장하는 표현 금지.
  - 개별 신고서를 사람이 검토해 주는 서비스를 하지 않는다(도구만 제공).
  - 판매 전 세무사 또는 변호사에게 서비스 형태와 문구를 확인받는다(`docs/legal/README.md` 확인 목록에 항목 추가).
- 개인정보: 이름·주민번호·계좌 입력칸 없음, 서버 전송 없음, 입력 파일은 사용자가 보관.
- 계산 규칙(공제 순서·기한)이 틀리면 사용자가 손해를 볼 수 있다. 규칙 파일 값에는 출처와 확인 날짜를 적는다.

## 6. 수용 기준

1. 가상 시나리오(결손 3개 연도, 한 해 공제 누락, 한 해 기한 경과)에서 의도한 경고(R-1~R-3)가 정확히 나온다.
2. 경고 없는 시나리오는 "어긋남이 보이지 않습니다"와 확인 안내만 나오고, "문제없음"이라는 단정 문구는 없다.
3. 공제 순서와 한도 계산이 단위 테스트로 보장된다(공개 가상 케이스 + 비공개 실제 사례 1건 이상).
4. 공개 빌드에 계산 코드가 없고(`check-public.js`가 검사), 체험은 시나리오 그대로일 때만 결과가 보인다.
5. 이름·주민번호·계좌 입력칸이 없고, 입력값이 서버로 나가지 않는다.
6. 모든 결과 화면에 "참고용, 세무사 확인 권장" 문구와 약관 링크가 있다.
7. 규칙 파일의 모든 값에 출처와 확인일이 있고, 미확인 값은 화면에 "확인 필요"로 표시된다.
8. 마법사의 각 단계는 끝나는 조건을 채워야 "다음"이 열리고, 뒤로 가서 값을 바꾸면 결과가 다시 계산된다. 중간에 "여기까지 저장"한 파일을 불러오면 그 단계로 돌아온다.
9. 모든 입력칸에 "어디서 찾나요?" 도움말이 있고, 값을 모르면 비워 둔 채 진행할 수 있다(비운 연도는 점검 불가로 표시).
10. 사용성 확인: 이월결손금을 처음 들어 본 사람 5명 중 4명 이상이 안내만 보고 연도 하나를 5분 안에 입력한다(비공개 시험, 가상 서식 사용).

**R1에서 PRD와 달라진 점**
- 입력값을 6개에서 **3개**로 줄였다: 소득금액(공제 전, 결손이면 음수), 신고서 공제액, 신고서 잔액(선택). 결손 발생액은 소득금액이 음수일 때 자동으로 정한다. 초보자 부담을 줄이려는 선택이다.
- **R-4(공제 순서 위반)는 후속**이다. 발생연도별 공제 내역을 입력받아야 알 수 있어서 R1 입력으로는 판단할 수 없다.
- R-6은 "입력 부호·연도 확인"으로 정리했다(소득금액이 0 이하인데 공제액이 있음, 공제액이 소득금액보다 큼).
- 환급 영향 추정(§3.5)은 넣지 않았다. 계산상 더 공제할 수 있었던 금액의 합만 "참고, 환급액 아님"으로 보여 준다.
- 점검 질문 6개는 구현했었으나 2026-11-02에 PRD에서 뺐다(코드 정리 필요).

**미확인·미검증**
- 공제 순서·기한 규칙, 서류 이름·칸 번호, 안내 문구(법령·세무 해석 미확인).
- 실제 사용자 시험(수용 기준 10)은 하지 않았다.
- 실서버(Cloudflare) 배포는 하지 않았다. 로컬 모의 서버로 이용권 확인 뒤 모듈을 받아 쓰는 흐름까지 확인했다.

## 9. 열린 질문 (결정 필요)

1. 가격과 포함 방식: 장부선생 이용권(50,000원, 현재 귀속연도)에 포함할지, **과거 연도 점검용 별도 이용권**(`plan: refund`)을 둘지. 지금 이용권 정책은 "현재 귀속연도만"이라 과거 연도 점검과 맞지 않는다.
2. 환급 영향 추정(§3.5)을 v1에 넣을지, 숫자 없이 "어긋난 해"만 보여 줄지.
3. 세무사 확인 범위와 비용(서비스 형태, 문구, 규칙 값). 누가 하는가.
4. 가족 여러 명 값을 한 이용권으로 점검해도 되는지(약관·기기 제한과 충돌 여부).
5. 입력 도우미를 글·그림 위주로 할지, 짧은 영상(화면 녹화는 가상 계정 필요)까지 만들지.
6. 블로그에서 어디까지 소개할지(사례 공개 범위, 개인정보, 광고 표현).
