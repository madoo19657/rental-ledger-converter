# PRD: 유료 이용권 상품화 (rental-ledger-converter 상용화)

- 상태: 초안 v0.1
- 작성일: 2026-11-01
- 범위: 이미 만든 단일 HTML 도구(변환 엔진·화면, [PRD.md](PRD.md))를 **블로그 글로 유입한 사용자에게 이용권(인증코드)을 판매**하는 상품으로 만든다. 도구 자체의 기능 요구는 `PRD.md`(F-1~F-36)가 정하고, 이 문서는 **판매·인증·배포·운영**을 정한다.
- **제품명: 장부선생** (2026-11-01 확정, 부제 "간편장부 → 복식부기 변환"; 슬로건 "간편장부를 복식부기로, 선생님이 차근차근 알려 드립니다"). 프로젝트 폴더 이름(slug)은 `rental-ledger-converter`를 유지한다(볼트·워크스페이스 이름 일치 규칙). 상표·도메인·검색 중복은 아직 확인하지 못했다(13장). **"선생"이 세무 전문가·대행으로 읽히지 않도록** 문구 규칙(5.9 C-5)을 지킨다.
- 이 문서에는 개인 금액·가족·계좌 정보가 없다(그런 자료는 볼트에만 둔다).
- **법령·서비스 약관·요금은 직접 확인하지 못했다.** 외부 서비스 이름은 후보이고, 가격과 조건은 도입 전에 확인한다. 법률·세무 자문이 아니다.

## 1. 배경과 목표

- 도구는 간편장부(엑셀)를 복식부기 재무제표와 홈택스 입력값으로 바꿔 준다. 브라우저 안에서만 동작해 장부 데이터가 밖으로 나가지 않는다.
- 소규모 임대사업자는 세무사 비용 부담이 크고 홈택스 입력이 어려워, **직접 신고하려는 수요**가 있다고 가정한다(검증 필요).
- 목표: 블로그 글(경험담·따라하기)로 유입 → **무료 체험** → **이용권 구매** → 신고 시즌에 도구 사용. 개인이 감당할 수 있는 운영 부담으로 **소액이라도 반복되는 수익**을 만든다.

### 목표
1. 방문자가 **가입 없이 가상 샘플로 체험**할 수 있다.
2. 구매자는 **이메일 + 6자리 코드**로 유료 기능을 푼다.
3. 코드 없이는 유료 기능(내 파일 업로드·조정계산서·홈택스 입력값)을 쓸 수 없다. 단, 우회를 **완전히** 막지는 않는다(5.7 위협 모델).
4. 사용자의 **장부 데이터는 서버에 보내지 않는다**(판매 포인트).
5. 운영자(나)는 **주말 몇 시간 이내**로 발급·문의·갱신을 처리한다.

### 비목표 (v1)
- 계정·로그인·결제 자체 구현(결제는 기존 판매 채널을 쓴다)
- 사용자 장부의 서버 저장·동기화·공유
- 신고 대행, 세무 상담, 신고서 작성 대행(법적 경계, 8장)
- 모바일 앱, 다국어
- 완전한 복제 방지(DRM)

| 운영자(나) | 판매·발급·응대 | 쉬운 발급, 최소한의 장애 대응, 비용 통제 |

## 3. 핵심 시나리오

1. **유입**: 블로그 글 → 도구 링크 → 가상 샘플 체험 → "내 파일로 쓰려면 이용권" 안내
2. **구매**: 판매 채널에서 결제 → 이메일로 **6자리 코드** 수령
3. **인증**: 도구에서 이메일 + 코드 입력 → 서버 확인 → 유료 기능 해제(토큰 저장)
4. **사용**: 엑셀 업로드 → 1~4단계 → 결과·홈택스 입력값 → 다음 방문 때 토큰으로 자동 해제
5. **갱신**: 이용권 만료 시 안내 → 재구매 → 새 코드
6. **문의**: 코드 분실·환불·오류 문의 → 운영자가 조회·재발급

**체험 버전 결과 화면 (2026-11-01)**
- 체험 버전은 가상 샘플 그대로일 때 **모든 탭(홈택스 입력값, 조정계산서, 수입금액명세서, 조정합계표 포함)**의 결과를 보여 준다. 유료 계산 코드는 화면에 없고, 빌드 때 샘플(상가A·B)의 유료 결과를 미리 계산해 넣는다(`scripts/build.js`의 demo).
- 입력을 하나라도 바꾸면(열쇠 `paidKey`가 달라짐) 유료 탭이 다시 잠긴다. 내 파일 업로드, 저장·불러오기·출력·분개장 내보내기도 계속 이용권이 필요하다.
- 샘플 설정은 `scripts/build.js`의 `sampleSettings`가 원본이다(화면의 샘플 버튼도 이 값을 쓴다). 화면 입력 형식이 바뀌어 열쇠가 어긋나면 체험 결과가 잠금으로 보이므로, 바꾼 뒤에는 브라우저에서 샘플 두 사업장 모두 확인한다.
- "이용권 입력" 버튼은 업로드 박스 안으로 옮겼다(이용권이 확인되면 숨김).

**Phase 1b 한계와 주의**
- 한 번 열린 화면의 계산 결과는 이용자가 복사·저장할 수 있다. 막는 것은 "계산 코드를 받아 가는 것"이지 결과가 아니다.

- 세법 값(`config/tax-params-2025.json`)은 아직 공개 화면에 들어 있다. 서버로 옮기려면 별도 작업이 필요하다.

## 6. 비기능 요구사항

- **개인정보**: 장부 데이터는 서버로 전송하지 않는다(S-2, L-9). 이것을 화면에 명시하고 사실과 일치하는지 주기적으로 점검한다.
- **가용성**: 인증 서버가 죽어도 유예 기간 동안은 사용 가능(E-3). 체험 모드는 서버 없이 동작.
- **비용**: 월 고정비를 낮게 유지(서버리스 무료 구간 우선, 확인 필요). 요금제 조건을 도입 전에 확인.
- **성능**: 인증 확인 응답 1초 이내를 목표, 도구 첫 로드는 현재 약 160KB 수준 유지(번들 포함 시 증가 예상).
- **브라우저**: 최신 Chrome·Edge·Safari 데스크톱, 모바일 읽기 가능.
- **접근성·사용성**: 기존 `user-manual.md`와 화면 기준 유지(금액 쉼표, 한글 표기, 필수 `*` 표시).
- **정확성**: 판매 전 세무사 검수와 사례 회귀 테스트(`tests/`)를 통과해야 한다.

## 7. 아키텍처 개요

```
[블로그 글] → [공개 도구 HTML: 체험 모드]
                 │ (이용권 입력: 이메일 + 6자리)
                 ▼
          [인증 API (서버리스)] ←→ [라이선스 저장소(KV 등)]
                 │ (성공 시) 토큰 + 엔진 번들(+세법 값)
                 ▼
     [브라우저: 엔진 실행, 내 장부는 이 안에서만 처리]

운영자: [관리자 스크립트] → 코드 발급/폐기/조회 → 이메일 발송
결제:   [판매 채널] → (수동 → 웹훅) → 발급
```

- 서버는 **인증과 엔진 전달**만 한다. 사용자의 장부는 받지 않는다.
- 서버 없이 시작하는 P0는 UI 잠금(우회 가능)이고, P1에서 엔진 배포를 서버로 옮긴다.

## 8. 법적·윤리적 제약

- **세무 업무 경계**: "신고 대행·세무 상담"이 아니라 "홈택스에 입력할 값을 계산해 보여 주는 도구"로 표현한다. 세무사법 등 요건은 **확인되지 않았다**(전문가 확인 필요).
- **면책**: 참고용 계산, 신고 책임은 사용자, 오류로 인한 가산세·손해 책임 범위, 세법 개정 반영 시점.
- **환불·청약철회**: 디지털 콘텐츠의 청약철회 제한 요건과 고지 방식(전자상거래법)을 확인한다.
- **사업 요건**: 사업자등록, 통신판매업 신고, 부가세·종합소득세 신고 대상 여부를 확인한다.
- **라이선스**: SheetJS(0.18.5)와 글꼴(나눔고딕 등)의 재배포 조건을 확인하고 번들에 포함할지 정한다.
- **개인정보**: 수집 최소화, 처리방침 게시, 외부 서비스(결제·메일·호스팅) 제3자 제공 고지.
- **출처 존중**: 국세청 자료·블로그 해설은 요약·재구성만 하고 원문을 복제하지 않는다(`sources.md`).

## 10. 수용 기준

1. **공개용 빌드에 개인 값 0건**: 금지 문자열 검사가 통과한다(B-2).
2. 잘못된 코드로는 유료 기능이 풀리지 않고 엔진이 내려오지 않는다(P1부터).
3. 같은 이메일로 설정한 횟수 이상 틀리면 잠긴다(L-4).
4. 만료된 이용권은 유료 기능이 잠기고 갱신 안내가 나온다(L-5).
5. 인증 요청과 서버 저장소에 **장부 데이터가 없음**을 코드와 로그 검사로 확인한다(S-1, S-2).
6. 체험 모드는 서버 없이도 동작한다.
7. 사례 회귀 테스트(`tests/`)가 모두 통과한다.
8. 면책·약관·처리방침 문구가 화면과 판매 페이지에 있다.

| **Phase 0** | 공개용 빌드(B-1~B-3), 체험 모드(T-1~T-4), 면책 화면, 이용권 입력 칸(UI 잠금) | 개인 값 0건, 체험 동작 |
| **Phase 1** | 인증 서버(L-1~L-5, S-1~S-6), 관리자 스크립트(O-1~O-3), 엔진 서버 배포(E-1~E-4), 약관·처리방침 | 코드 확인·만료·잠금 동작 |
| **Phase 2** | 결제 웹훅 자동 발급, 만료 안내, 기기 제한 | 운영 자동화 |
| **Phase 3** | 이월결손금 기능, 추계 비교 등 기능 추가, 세법 값 연도 갱신 | 시즌 대비 |

판매 개시는 Phase 1(1a·1b) 완료와 세무사 검수·약관·처리방침·사업자 요건 확인, 2026 귀속 세법 값 갱신 후로 한다.

## 13. 열린 질문 (결정 필요)

1. 서버를 직접(Cloudflare Workers 등) 운영할지, 판매 플랫폼의 라이선스 키를 쓸지
2. 6자리 숫자 코드로 확정할지, 길이를 늘릴지(이메일 결합·시도 제한이 전제)

4. 이용권 기간(귀속연도 단위) 과 가격
5. 기기 제한 N과 이메일 필수 여부
6. 판매 채널과 결제 방식, 사업자 형태
7. 세무사 검수 범위와 비용, 약관·처리방침 작성 방식(전문가 검토 여부)
